# KOLBB 实现与交付记录

2026-09-10。设计依据为 GDD 及视觉圣经；原始设计文档未改写为测试结果。

## 游戏实现

`scripts/battle.gd` 是不依赖场景树的固定点模拟。人物坐标使用 1/256 像素整数，所有招式伤害、食物、定格、投技演出、MAX 和胜负都由 60Hz 模拟产生。普通攻击数据从 GDD 提取到 `assets/moves.json`；美术动画不决定命中。

`commands.gd` 处理 SOCD、相对方向、指令优先级、组合键宽容和输入缓冲，解析状态包含在快照内。`cpu.gd` 根据延迟后的公开局面决定输入，三档分别使用 24／16／10 帧观察延迟。

`rollback.gd` 使用 3 帧输入延迟、最多 12 帧预测、20 份快照与 240 帧输入历史。校验序列化使用排序键、类型标记和小端整数，CRC32 查表计算。每 60 帧校验，终局双方确认后才显示正式结果。短音效事件去重，终局音效等待确认。

`network.gd` 使用 Godot ENet：可靠控制、非可靠冗余输入、可靠补帧三个通道。房间最多四个，每房两人；服务器验证输入来源、范围、顺序与不可变性，并限速。房间空闲、未入房连接、掉线、版本不符和校验不一致均有退出路径。房间码避开 I／O／0／1。

客户端有主菜单、选人、三档 CPU、出招表、设置、房间准备、战斗、暂停和结算。支持自定义键位、音量、全屏、减少闪光、关闭震屏，以及本地累计胜场、最佳连击与完美终局记录。

## 美术与声音

图像通过内置 ImageGen 生成，以本项目参考图和统一 `design/style.txt` 约束身份与风格。Higgsfield CLI 用于两首音乐与一次重击音效；没有把 ImageGen 图像或本地合成音效标为 Higgsfield 产物。

每人九组、每组 24 个图集单元，共 432 个基础角色单元；另有程序调色的镜像配色。分组包含基础、移动、防御与倒地、入场与胜利、地面普通攻击、空中四攻击以及特殊技。部分接触与受击姿态复用。

生产导入会识别透明色之间的实际行列间隔，统一人体尺度和脚底定位，再打包为 `SpriteFrames` 资源。为容纳低扫和皮鞭的完整轮廓，人物统一扩大为 **384×224 单元、脚锚点 192,208、4 列×6 行**，单张图集 1536×1344；这是视觉圣经允许的扩大单元方案。运行时采用 nearest，无 mipmap。JU 的胸标在反向绘制时单独纠正文字朝向。

背景为 640×360 办公室，界面文字由 Godot 字体绘制。小道具和召唤／门／桌子的动画独立于人物。食物保留槽位形状、数字、激活状态、危险提示和过期提示。火花、定格、震屏、血条残影、连击数字和分层音效组合呈现命中；关闭震屏延长火花两帧，减少闪光不改变模拟。

39 个运行时音频文件包括：Higgsfield Sonilo 菜单与战斗曲各一首、Seed Audio 重击一条、本地原创合成音效 34 条，以及胜利短曲和紧张节奏各一条。音乐以首尾交叉淡化衔接，约 -20 LUFS；重击与其他音效分别归一化后再受主音量和音效音量控制。`tools/make_sfx.py` 可重建合成部分，`design/*_job.json` 保留 Higgsfield 生成记录。

## 已运行验证

设备：MacBook Pro，Apple M2 Pro，16GB 内存；Godot 4.7.2 Compatibility。下列是本机实测，不代表其他机型。

| 验证 | 结果 |
| --- | --- |
| 规则回归 | 120 项通过；固定重演 CRC32 219921741 |
| 高级技能 | 投打优先级、拆投、指令投、五波大招、打断、召唤击飞、食物／KO 次序、MAX 和演出超时通过 |
| 延迟回滚 | 2200 帧，2–6 tick 延迟及反复丢包，双端最终状态一致 |
| CPU 长跑 | 12 场完整对局，92693 tick，无状态越界；一轮常态模拟 p95 为 53µs |
| 网络条件模拟 | 32 场完整对局，5% 丢包、±2 tick 抖动、500ms 断流，最终状态全部一致 |
| 优化后回滚峰值 | 同一组 32 场测试为 2941µs，59615 次校正；低于 8ms 目标 |
| 实际绘制帧间隔 | 3 秒预热后采样 15 秒、1831 帧；墙钟间隔 p95 为 13.164ms，末次 FPS 126；显存约 400MB |
| 本机 ENet | 两个独立进程完成一场对局、双方结果确认及再战，退出码均为 0 |
| 公网 ENet | 两客户端连接 49.235.23.27，完成两场及再战；双方终局 CRC 分别为 2024687692、3820668219 |

`tests/visual_qa.gd` 输出主菜单、选人、设置、出招表、八招及两个镜像场景，并检查所有图集单元边界。游戏 F3 可显示真实判定盒。`--verify-assets` 检查发行包中的音频、图集和头像，避免仅源码模式可加载的问题。

最终图集的 432 个单元均通过边界检查，14 个界面／战斗场景完成渲染检查；额外验证了接触姿态不提前、首末有效帧保持接触、收招在有效帧之后。菜单退出连续释放五个房间并取消未完成连接的检查通过。最终 art-2 版本公网 700 帧双端 CRC 均为 3207853262。

最终导出的 `KOLBB.app` 通过签名完整性检查，二进制架构为 x86_64／arm64；发行包自检加载到 39 个音频、36 张人物图集、两份 SpriteFrames 和动画道具。通过发行版真实菜单建房并与测试客户端完成公网对局，服务器在输入帧 3262 确认比分 0:2、CRC32 3796547687；发行版显示正式结果，Esc 正常退房并返回主菜单。该阶段服务器没有再出现向断开连接发送控制包的错误。

帧间隔通过单调墙钟测量，原始记录在 `build/performance.json`。同轮 Godot `TIME_PROCESS` 监视器采样 p95 为 41.329ms，与墙钟帧间隔口径不同，保留原值，未据此宣称该监视器达到 16.7ms。渲染验证只覆盖这台 Mac 的一次 18 秒运行，不替代两台目标设备的持续验收。

## 公网服务

已部署到 `ubuntu@49.235.23.27`，Ubuntu 24.04 x86_64。服务用户为 `kolbb`，UDP 7000，由 systemd 管理，开机启动并故障重启。正常空闲约 40MB 内存。公钥及云防火墙配置由用户完成，项目中不保存私钥或密码。

部署文件在 `server/`；日志每天轮转保留七份。更新服务器会中止当前房间，更新前应确认无人对战。客户端及服务端必须使用相同版本标识。

## 仍需外部验收

本环境只有一台实际 Mac，尚未完成 GDD 要求的两台目标 Mac、Intel 硬件、不同公网接入环境的人工试玩与帧时记录。也尚未完成每个角色两人轮换的新手搓招成功率及平衡性统计。当前美术由生成图稿制作，部分动作姿态复用，仍应通过人工逐招试玩评估流畅度。以上不以自动化通过代替。

macOS 包包含两种架构，使用临时签名，未提交 Apple Developer ID 签名和公证。发布到陌生用户前需要开发者账号完成这一发行步骤。
