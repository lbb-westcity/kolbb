# 联机与常见问题

[返回百科首页](README.md) · [新手入门](getting-started.md)

## 桌面端和好友开一局

1. 双方及服务器使用 0.1.2 / rules-3，主菜单选择「互联网对战」。
2. 填写相同的服务器地址；当前项目默认配置为 `49.235.23.27`，这不代表百科已验证该地址实时在线。
3. 一方选择「创建房间」，将六位房间码告知好友。
4. 另一方输入房间码并选择「加入房间」。房间码是字母与数字组合，输入会自动转大写并过滤无效字符。
5. 在房间中切换角色，双方点击「准备」后开始。支持相同角色。
6. 结束后可选择「再战」，双方准备后继续；或回房间重新选人。

目前是无需账号的双人好友房间，没有排位匹配、观战、聊天或本地双人模式。服务器当前最多四个双人房间，使用 UDP 7000。自行部署见[服务器部署与维护](../DEPLOYMENT.md)。

## 微信好友对战

选择「好友对战」→ 创建房间 → 选择角色 → 点击「邀请微信好友」。好友打开分享卡片自动加入，也可用原生键盘输入六位房间码；双方准备后开战。打开邀请面板不会退出等待中的房间，进行中的对局不会被新邀请打断。

微信使用构建时配置的服务器地址；未配置时好友页会提示暂不可用。微信与桌面使用独立房间，不能跨端加入同一场对战，各自最多四个双人房间。正式微信联机需配置 WSS 域名；构建、调试包与真机验收进度见[微信说明](https://github.com/lbb-westcity/kolbb-minigame/blob/main/docs/WECHAT_VALIDATION.md)。

<h2 id="version-compatibility">版本兼容与升级</h2>

当前网络版本标识为 `kolbb-0.1.2-rules-3-art-3`。本轮同步三角色平衡、MAX 费用与 CPU 输入，并统一跨引擎版本的状态校验。客户端与对应服务端必须使用同一规则；桌面版 0.1.3 沿用该兼容标识；rules-2 与 rules-3 不能互联，版本不一致时会提示「版本不一致，请更新游戏」。

玩家更新配套的 macOS 或 Windows 客户端；服主使用同版 Ubuntu 服务器包，按[更新流程](../DEPLOYMENT.md)备份、安装并验证。服务重启会清空房间，升级后重新建房。单独更新本 Wiki 的静态页面无需更新或重启游戏服务。

## 暂停与断线

**单机**按 Esc、触屏暂停按钮或切出应用会暂停，恢复前有 3 秒倒数。**线上**打开菜单或出招表不会暂停对局，菜单期间你的战斗输入保持中立。桌面切出应用也不暂停；微信切后台则结束本场、不计结果。

联机使用输入同步与回滚。画面可能先展示预测的攻击反馈，正式回合与胜负提示等待输入确认。连接中断、输入冲突、校验不一致或结果确认超时会结束为本场无结果，不判任意一方获胜。

## 常见问题

| 问题 | 处理方式或原因 |
| --- | --- |
| 提示版本不一致 | 双方客户端与对应服务端均升级到 0.1.3 / rules-3；只更新客户端或 Wiki 不够 |
| 房间不存在或已结束 | 核对六位码，确认好友仍在原房间；必要时重新创建 |
| 房间已满 | 房间已经有两人，或已进入对战 |
| 服务器房间已满 | 当前四个房间已占用，等空位或使用另一台服务器 |
| 一直连接不上 | 核对地址和服务状态；桌面服务需要放行 UDP 7000，微信服务需配置 WebSocket 地址，详见各端部署说明 |
| 提示需要能量 | 查看实际消耗；MAX 内超必杀本次需要 100 |
| 提示场上已有同类道具 | 等自己的飞行道具、汉堡，或召唤及披萨消失后再用对应招式 |
| 吃汉堡反而掉血 | 那是对手的汉堡；镜像同样按玩家归属判断 |
| 走到食物旁没有吃 | 可能仍在落地等待期、自己满血、非自由状态或有拾取间隔；对手披萨不能吃 |
| 按 A 没有轻拳 | 出招表 A 是动作记号，默认轻拳键是 J |
| 超必杀或必杀没出来 | 核对朝向、指令时限、能量及是否接地；换边后重新输入 |
| 翻滚中被抓 | 翻滚仅在中间 12 帧免疫打击，全程仍可被合法抓取 |
| 站防被扫倒 | 蹲轻脚和重扫腿是低段，需要下后蹲防 |
| 蹲防被跳攻击击中 | 空中普通攻击是中段，需要站防 |

## 设置与记录

桌面设置提供主音量、音乐、音效、1920 × 1080／2560 × 1440 窗口分辨率、全屏、震屏、减少闪光和十项按键绑定。全屏采用屏幕原生分辨率，像素画面保持整数缩放。微信触屏设置另提供方向死区与按钮不透明度。

绑定冲突时交换两项按键，可恢复默认。设置自动保存到 Godot 用户数据目录中的 `settings.cfg`；不是项目根目录下的文件。结算显示累计胜场、最佳连击与完美终局；累计胜场和完美终局由单机结算记录，完美终局指赢得整场时自己的生命为满值。

rules-3 已通过本机双客户端完整对局与再战校验；本轮未升级或验收公网游戏服务，微信 Android／iPhone 真机验收仍待完成。安装、系统拦截与发行包说明见[项目 README](../../README.md)。
